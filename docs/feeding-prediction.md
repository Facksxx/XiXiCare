# 预计下次喂奶时间：推算逻辑说明

> 实现文件：`src/utils/feedingPrediction.ts`（算法）、`src/utils/feedingIntervals.ts`（有效间隔）
> 展示位置：时间轴（Records）页顶部「预计下次喂奶」横幅
> 最后更新：2026-10-01

## 1. 目标

在「时间轴」页顶部给出下一次喂奶的预计时刻，帮助家长安排下一次喂养，同时避免在数据不足或情况已经远离预测时给出误导性提示。

预测基于宝宝自己的历史喂养记录，不使用任何标准月龄参照表——每个宝宝的节奏差异很大，自己的数据最准。

## 2. 输入数据

| 项目 | 说明 |
| --- | --- |
| 数据来源 | `src/types/baby.ts` 的 `ActivityLog`，只取 `logType === 'feeding'` 的记录 |
| 时间戳 | `log.timestamp`（ISO 字符串，本地时刻） |
| 喂养方式 | `metadata.feedingType`：`breast` 母乳亲喂 / `bottle` 瓶喂 / `solids` 辅食 |
| 奶量 | `metadata.bottle.volumeMl`（仅瓶喂有值），用于奶量修正 |
| 当前时间 | 每 30 秒刷新一次（Records 页 `nowTick`），保证超时后预测能自动隐藏 |

## 3. 有效间隔的定义

相邻两次喂养之间的时间差并不都能用：刚喂完又补几口、隔夜漏记都会污染样本。`getEffectiveFeedingIntervals()` 按下面的规则筛选：

1. 只比较「相邻两次」喂养记录（按时间戳排序，时间戳相同时按 id 排序，保证顺序稳定）；
2. 间隔 **≤ 30 分钟** 视为同一次喂养的补记，不计入样本；
3. 间隔 **> 24 小时** 视为漏记，不计入样本；
4. 命中 2 或 3 的间隔被丢弃后，下一次比较的起点会顺延到当前这条记录，避免一个漏记把后续间隔整体算错。

## 4. 推算流程

算法共 5 步，输出一个预测时刻。

### 第 1 步：确定基准记录

取全部喂养记录里最新的一条作为 `lastFeedingAt`。若它距当前时间超过 **6 小时**，直接放弃预测（见第 6 节）。

### 第 2 步：取窗口内的有效间隔

只保留最近 **7 天** 内的有效间隔。窗口太短样本不足，太长则跟不上宝宝当前的变化节奏。

### 第 3 步：计算样本权重（近期更重要）

宝宝的吃奶间隔会随着月龄增长而逐渐拉长，所以越近的记录越有代表性。每条间隔的权重按半衰期衰减：

```
weight = 0.5 ^ (距今天数 / 2.5)
```

即今天产生的间隔权重为 1，2.5 天前的为 0.5，5 天前的为 0.25。**半衰期 2.5 天** 是折中值：既能快速反映最近的作息变化，又不会让单条记录左右结果。

### 第 4 步：判断下一顿落在白天还是夜间

白天和夜间的喂养间隔通常差别很大（白天可能 2-3 小时，夜里常有 4-6 小时的长觉）。把两者混在一起取平均，会造成系统性的偏差：夜里预测偏早、白天预测偏晚。

1. 先用全部样本算一个全时段基准 `overallBase`；
2. 用 `lastFeedingAt + overallBase` 得到下一顿的大致落点；
3. 落点在 **22:00-06:00** 之间即为夜间，否则为白天；
4. 取对应时段的间隔样本；**该时段样本少于 4 条** 时回退到全部样本（新用户数据少时不硬套分档）；
5. 每个间隔按其**中点**所在时段归档——跨昼夜的长觉（如 21:30 → 03:00）不会因为结束时刻是清晨就被算成白天样本。

### 第 5 步：稳健加权均值

在选中的样本上计算基准间隔，两步走：

1. 先算加权均值，得到分布中心；
2. 计算加权 **MAD**（各样本与中心的绝对偏差的中位数），剔除偏差超过 **2.5 × MAD** 的间隔，再对保留样本重新加权平均；样本少于 5 条时跳过剔除。

为什么不用普通平均：一顿漏记（比如 11:30 → 21:30 的 10 小时）就会把均值拉高半小时以上。
为什么不用中位数：夜间常常是「上半夜长觉 + 下半夜短觉」的双峰分布，中位数只会取到其中一个端点值，反而不如截尾均值贴近真实情况。

### 第 5.5 步：瓶喂奶量修正（启发式）

若最近一次是瓶喂，且历史瓶喂记录里有 **≥ 5 条** 奶量样本：

```
ratio     = clamp(本次奶量 / 历史奶量中位数, 0.6, 1.6)
修正量    = clamp(基准间隔 × 0.3 × (ratio - 1), ±基准间隔 × 8%)
```

即这顿明显喝得更多时，下一顿稍微推后一点，反之提前。系数取得很保守（最多 ±8%），它是经验性微调，不参与「分时段 + 稳健均值」的主逻辑；非瓶喂或奶量样本不足时该修正为 0。

### 输出

```
predictedAt = lastFeedingAt + (基准间隔 + 奶量修正) × 60 秒
```

同时返回给界面：`sampleCount`（参与计算的样本数）、`period`（day / night）、`periodScoped`（是否真的用了分时段样本）、`lastVolumeMl`、`volumeAdjustmentMinutes`。

## 5. 参数一览

| 常量 | 取值 | 含义 |
| --- | --- | --- |
| `FEEDING_PREDICTION_WINDOW_DAYS` | 7 天 | 取样窗口 |
| `FEEDING_PREDICTION_HALF_LIFE_DAYS` | 2.5 天 | 权重半衰期 |
| `FEEDING_PREDICTION_MIN_PERIOD_SAMPLES` | 4 条 | 分时段样本下限，低于则回退全时段 |
| `NIGHT_START_HOUR` / `NIGHT_END_HOUR` | 22 / 6 | 夜间时段定义 |
| `MIN_FEEDING_INTERVAL_MINUTES` | 30 分钟 | 有效间隔下限 |
| `MAX_FEEDING_INTERVAL_MINUTES` | 24 小时 | 有效间隔上限 |
| `FEEDING_PREDICTION_MAX_GAP_MS` | 6 小时 | 显示 / 隐藏阈值 |
| MAD 剔除倍数 | 2.5 | 离群间隔判定 |
| 奶量修正强度 / 上限 | 0.3 / 8% | 瓶喂启发式修正 |

## 6. 隐藏规则

以下任一情况成立时返回 `null`，界面不显示横幅：

1. 没有喂养记录；
2. 上一次喂奶距现在超过 **6 小时**（记录可能已过期，或今天没记）；
3. 当前时间与预测时刻相差超过 **6 小时**（预测已经严重偏离，不如不显示）；
4. 最近 7 天内没有任何有效间隔。

## 7. 边界与回退

| 场景 | 行为 |
| --- | --- |
| 新用户，只有 1-2 条间隔 | 直接使用这 1-2 条样本（`periodScoped = false`） |
| 只有白天数据、但下一顿在夜里 | 分档样本不足 4 条 → 回退全时段样本 |
| 时间戳非法 | 过滤掉该记录，不参与计算 |
| 全部是亲喂、没有奶量 | 奶量修正为 0，不影响主逻辑 |
| 时间戳相同时 | 按 id 二次排序，保证多次计算结果一致 |

## 8. 与旧算法（2026-10-01 之前）的差异

| 维度 | 旧算法 | 现算法 |
| --- | --- | --- |
| 取样 | 最近 7 天全部有效间隔 | 最近 7 天，先分昼夜再取样 |
| 权重 | 等权 | 按半衰期 2.5 天指数衰减 |
| 统计量 | 算术平均 | MAD 截尾加权均值 |
| 奶量 | 不考虑 | ±8% 启发式修正 |
| 界面文案 | 「平均 3小时24分钟」 | 「夜间基准 4小时27分钟」 |

用同一批模拟数据（白天 2.5 小时一顿、夜里 21:30 睡下后 03:00 才吃）对比：旧算法给出约 3 小时 15 分的全时段均值，夜里预测因此偏早约 1.5 小时；现算法在夜间场景给出 267 分钟（约 4 小时 27 分）的夜间基准，与真实节奏吻合。

## 9. 验证方式

`tmp/prediction-test/` 下有一套不依赖界面的断言脚本：

```bash
npx esbuild src/utils/feedingPrediction.ts --bundle --format=esm --platform=node \
  --outfile=tmp/prediction-test/prediction.mjs
node tmp/prediction-test/run.mjs
```

覆盖 19 项断言：昼夜分档生效、夜间基准明显高于白天、离群间隔不影响结果、样本不足回退、6 小时隐藏规则、空数据、奶量修正幅度上限、时段边界（22:00 / 21:59 / 05:59 / 06:00）。改动算法后应先跑这套脚本。

## 10. 已知取舍与后续可做

- **未做区间展示**：可以给出「预计 02:30（±40 分钟）」的置信区间，但对家长的决策帮助有限，暂不增加界面复杂度。
- **6 小时阈值偏紧**：大月龄宝宝夜间可能睡 8 小时以上，届时预测会直接隐藏。若要支持，可按宝宝月龄放宽上限。
- **未使用睡眠数据**：夜觉结束后第一顿的间隔通常更短，如果能结合睡眠记录（`logType === 'sleep'`）会更准，但依赖「睡眠记录是否完整」，暂不引入。
- **奶量修正为经验值**：目前只有 ±8% 的弱修正，缺乏回归验证；若有足够真实数据，可以换成按奶量分档的统计模型。
- **辅食阶段**：`solids` 记录的间隔特征与奶不同，目前与奶同等对待，未来可单独分档。
